# 프레임워크에 독립적인 TUI 설계 원칙

상태: 초안. 아래 규칙은 LazyOra 조사에서 일반화한 프로젝트 기준이며, 외부에서 승인된 범용 TUI 표준은 아닙니다. 출처와 제품 적용 사례는 [로드맵](roadmap.md) 및 [LazyOra 제안서](https://github.com/leechis7/lazyora/blob/a38c46ed7f5d85e1fc8f823ef4bfe6fabfdb17f7/docs/ui-style-proposal.md)를 참고하세요.

## 1. 스타일은 의미에서 결정한다

규칙: 기본 팔레트 → 의미별 토큰 → 컴포넌트/상태 순으로 해석합니다. 토큰의 역할은 색상 값과 별도로 유지합니다.

- 본문, 입력, 안내, 선택, 경고, 오류는 서로 다른 의미입니다. 같은 색으로 표시되는 환경에서도 같은 토큰으로 합치지 않습니다.
- 스타일은 테마·단말 능력·컴포넌트·상태·실제 배경으로 결정합니다. 글자색과 배경색을 함께 정의합니다.
- 컴포넌트는 RGB나 ANSI 번호를 직접 고르지 않습니다. 제목과 읽기 전용 폼 설명도 해당 역할과 배경의 조합을 사용합니다.
- 앱 고유의 ‘미커밋 셀’은 범용 ‘변경됨’ 상태를 확장한 사례로 둘 수 있습니다. 공통 토큰에 Oracle 용어를 넣지 않습니다.

검증: 같은 값인 토큰 A/B를 서로 다른 값으로 바꾸었을 때 각각 올바른 영역만 갱신되어야 합니다. 색상 값 역추적으로 역할을 추측하면 실패로 봅니다.

## 2. 테마와 단말 능력을 분리한다

규칙: 사용자 테마는 모양의 선택, 색상 프로필은 표현 능력입니다. 어두운 테마라고 True Color가 되는 것은 아닙니다.

- 최소 기준 프로필은 ANSI8, ANSI16, Indexed256, TrueColor입니다. 무채색 테마는 각 프로필에서 별도로 해석합니다.
- 색상 수, 입력 키, 마우스, 선 문자, 굵게의 동작을 독립된 능력으로 기록합니다.
- ANSI 번호의 참조 RGB와 실제 사용자 팔레트를 구분합니다. 프로그램이 팔레트를 바꿔 검증 결과를 맞추지 않습니다.
- 제한 프로필에서는 중요도가 낮은 색상 차이를 포기할 수 있습니다. 조작·상태의 의미는 유지해야 합니다.
- 라이브러리의 색상 근사가 가능한 것과 디자인이 읽기 좋다는 것은 별도로 검증합니다.

검증: 프로필에 허용되지 않은 인덱스가 없어야 합니다. 자동 근사가 있다면 어떤 역할에 쓰였는지 기록하고 합성 뒤 대비도 확인합니다.

## 3. 포커스·선택·변경됨을 분리한다

규칙: 포커스는 다음 입력의 대상, 선택은 사용자가 고른 항목, 변경됨은 데이터의 상태입니다.

| 상태 | 기본 표현 | 대체 표현/제약 |
| --- | --- | --- |
| 포커스 | 강한 경계와 이중선 또는 전용 표식 | 단순 문자 단말에서는 ASCII 경계/표식 |
| 선택 | 읽을 수 있는 선택 전경·배경 | 단일 선택 목록의 `>` 등. 다중 선택은 체크 상태와 구분 |
| 변경됨 | 배경 또는 독립된 상태 표시 | `*`나 ‘변경됨’ 문구를 유지 |
| 오류/경고 | 의미별 색과 짧은 설명 | 색 없이도 오류/경고임을 알 수 있어야 함 |
| 비활성 | 비활성 스타일과 동작 차단 | 필수 설명을 희미하게 숨기지 않음 |

상태 합성은 컴포넌트에서 명시합니다. 예를 들어 입력 중 → 현재 선택 → 변경됨 → 일반/줄무늬 순으로 배경을 결정할 수 있습니다. 선택이 변경 배경을 덮어도 변경 표식은 유지합니다. 이 순서는 범용 강제 순서가 아닌 그리드 구현 예시입니다.

검증: 포커스를 다른 영역으로 옮겨도 선택/변경 정보가 남아야 합니다. 표식은 표시 계층에만 존재하며 원본 값·복사·내보내기 데이터를 오염시키지 않아야 합니다.

## 4. 제한된 색에서도 읽을 수 있어야 한다

규칙: 참조 팔레트에서 일반 텍스트 4.5:1, 포커스 경계 3:1을 내부 검토 목표로 삼고, 실제 단말 결과를 함께 기록합니다. 이는 접근성 인증 기준 선언이 아닙니다.

- 기본 전경색에 Bold를 켰을 때 밝은색으로 바뀌는 모델도 확인합니다.
- 본문·안내·NULL 등 필수 정보는 Dim만으로 표현하지 않습니다.
- 흑백에서도 선택·오류·처리 중·변경됨을 식별할 수 있어야 합니다.
- 대비가 부족한 색은 덜 중요한 장식으로 제한하거나 본문색으로 대체합니다. 8색에서 모든 문법 종류를 다른 색으로 구분할 필요는 없습니다.
- 굵기·밑줄·반전도 지원 여부가 다를 수 있으므로 문자 표식과 내용을 함께 평가합니다.

검증: 팔레트 계산, 상태를 합성한 실제 위젯 캡처, 단말 관찰 결과를 서로 구분합니다. 비활성 항목이나 장식선까지 모두 같은 대비 집계로 ‘버그 수’를 만들지 않습니다.

## 5. 컴포넌트별 조작 계약을 정한다

규칙: Tab/Shift+Tab은 영역 간, 방향키는 목록·그룹 내부 이동의 기본으로 삼습니다. 앱별 키맵은 이 계약을 확장하며, 특정 제품의 F키 배치는 공통 표준으로 강제하지 않습니다.

- 입력: 라벨, 입력 영역, 커서 위치가 보입니다. 선택박스는 펼침 표시를 추가합니다.
- 버튼: 포커스, 기본 동작, 위험 동작을 구분합니다. 외형 변경으로 Enter 기본 동작을 바꾸지 않습니다.
- 목록/트리/탭: 현재 선택과 키보드 위치를 확인할 수 있으며 항목 확정 시점을 문서화합니다.
- 메뉴: 구분선은 선택 대상이 아니며 하위 메뉴 이동/복귀와 최상위 이동 규칙을 명시합니다.
- 모달: 내부 포커스 순환, 배경 입력 차단, 닫기 후 호출 지점 복귀가 기본입니다. 외부 클릭으로 확정하지 않습니다.
- 취소: 먼저 열린 드롭다운·진행 중 입력 등 현재 단계부터 처리합니다. 실행 취소 가능 여부는 앱의 작업 상태 계약으로 정합니다.

검증: 키보드만으로 필수 동작을 완료할 수 있어야 합니다. 마우스 제공 환경에서는 선택/확정 의미가 키보드와 일치해야 합니다.

## 6. 셀과 레이어를 기준으로 배치한다

규칙: 너비는 바이트나 문자열 길이가 아닌 실제 표시 셀 수로 계산합니다. 전체화면 레이어와 자식 위젯의 그리기·입력 순서를 일치시킵니다.

- 한글 2셀·결합 문자·선 문자에 대한 환경 차이를 고려합니다. 픽셀 단위 CSS를 그대로 가져오지 않습니다.
- 불투명 팝업은 빈칸·여백까지 채웁니다. 드롭다운은 한글 문자의 절반만 덮어 이전 문자가 남는 상황도 정리합니다.
- 작은 창에서는 여백 축소와 스크롤을 사용하고 확인/취소 경로를 유지합니다.
- 말줄임에는 원문을 확인하는 경로를 제공합니다. 경고·오류·기본 버튼을 잘라내지 않습니다.
- 셀 간격·카드 크기는 공통 원칙과 별도의 디자인 기본값입니다. LazyOra의 좌우 2셀/상하 1행은 한 가지 사례입니다.

검증: 여러 크기에서 레이아웃을 다시 계산하고, 겹치는 위치의 클릭이 앞 레이어에만 전달되는지 확인합니다.

## 7. 테마 변경은 상태를 보존한다

규칙: 스타일은 현재 토큰에서 다시 적용하며, 화면 재생성이나 과거 색상 치환에 의존하지 않습니다.

검증: 테마 왕복 전후에 입력값·선택·스크롤·포커스·작업 상태가 같아야 합니다. 숨겨진 탭/페이지도 나중에 열었을 때 올바른 스타일을 가져야 합니다. 동일 스타일을 두 번 적용해도 결과가 같아야 합니다.

## 8. 원칙은 근거와 예외를 함께 보관한다

각 항목은 다음 형식으로 확장합니다.

```text
ID: focus.selection.separation
상태: 제안 / 참조 팔레트 검증 / 앱 캡처 검증 / 실제 단말 확인
문제: 선택과 입력 위치가 같은 것으로 보임
규칙: 선택 상태와 포커스 표시를 독립적으로 유지
적용 대상: 목록, 탭, 그리드
예외: 입력 자체가 선택 대상인 컴포넌트는 조작 계약을 추가 설명
검증: 선택 후 다른 영역으로 이동, 무채색에서도 선택/포커스 식별
근거: 공식 자료 링크 + 앱 사례/캡처 + 확인한 단말 정보
```

하나의 상태를 전체 가이드에 일괄 부여하지 않습니다. 원칙, 테마 값, 어댑터, 컴포넌트, 단말 관찰마다 검증 수준을 표시합니다.
