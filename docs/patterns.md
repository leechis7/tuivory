# 컴포넌트 패턴

**한국어 (기본)** · [English](patterns.en.md)

아래는 공통 설계 계약의 초안입니다. 프레임워크별 키 이벤트·포커스 구현은 어댑터가 담당합니다. [정적 배치 예시](../examples/components.txt)를 함께 보세요.

| 컴포넌트 | 기본 상태 | 포커스·선택 | 조작 계약 |
| --- | --- | --- | --- |
| 입력 | 라벨과 입력 면을 구분, 값과 커서 표시 | 입력 위치와 라벨/경계를 표시 | Tab 이동, 편집 키는 사용자 키맵 |
| 선택박스 | 펼침 표시 `v` 또는 `▾` | 현재 값과 펼친 목록의 선택을 구분 | 펼침/이동/확정/취소 순서 명시 |
| 버튼 | 읽을 수 있는 전경/배경과 공통 외형 | 포커스와 기본 버튼은 별도 상태 | 그룹 내 방향키, 확정은 Enter/Space 중 앱 계약 |
| 목록·트리 | 항목·계층·확장 상태 구분 | 선택과 입력 포커스 독립 표시 | 내부 방향키, 확정 시점 명시 |
| 탭 | 현재 문서/영역을 식별 | 활성 탭과 포커스는 다른 상태 | 탐색·활성화·닫기 계약 명시 |
| 표·그리드 | 헤더와 본문 구분 | 현재 셀·범위·변경됨을 합성 | 선택/복사/편집을 분리 |
| 메뉴 | 기능 그룹과 하위 메뉴 표시 | 구분선은 선택 대상에서 제외 | 최상위 이동·하위 진입·복귀를 구분 |
| 모달 | 불투명 카드·내부 여백·제목 | 내부에서 포커스 순환 | 배경 입력 차단, 닫은 뒤 호출 지점 복귀 |
| 상태·오류 | 의미와 다음 행동을 짧게 설명 | 색 외에 문구·기호를 제공 | 필요한 경우 상세/취소 경로 제공 |

## 상태 합성

일반 상태 위에 변경됨·선택·편집 중·오류가 겹칠 수 있습니다. 역할별 전경/배경을 조합하되 최종 조합도 대비를 확인합니다. 예를 들어 현재 셀의 선택 배경이 변경 배경을 덮어도 행 표식 `*`나 ‘변경됨’ 문구는 유지합니다. 표식은 실제 값이나 복사 데이터에 넣지 않습니다.

## 팝업과 단말 셀

빈칸도 카드의 일부입니다. 팝업 내부를 먼저 칠한 뒤 자식 위젯을 그리며 한글 2셀 문자의 절반이 이전 레이어에 남지 않도록 처리합니다. 단말별 문자 폭 차이도 기록합니다.

기본 예시 간격은 카드 좌우 2셀·상하 1행, 라벨/입력 사이 1셀, 버튼 사이 2셀입니다. 이는 조정 가능한 예시이며 의무 규격은 아닙니다. 작은 창에서는 간격부터 줄이고 내용 스크롤·확인/취소 경로를 유지합니다.

## 패턴마다 남길 정보

문제 → 역할/상태 → 키보드·마우스 계약 → 제한 단말 fallback → 검증 장면 → 알려진 예외를 기록합니다. 도구가 계산한 대비와 실제 단말 확인을 하나의 통과 표시로 합치지 않습니다.

## 공통 Tree 구현

위 표의 트리 계약은 [Tree API](tree.md)에서 Go/tview·Rust/Ratatui로 구체화했습니다. 선택·포커스를 분리하고 앱은 노드 데이터·실행·로딩을 연결합니다. 탭·분할 패널·상태 표시줄·경로도 [공통 워크스페이스](workspace.md)로 구현했습니다.

## 공통 상태·포커스 구현

[TVR-8](focus.md)은 상태 합성·ID 탐색·중첩 모달 입력 차단·닫기 요청·포커스 복귀를 Go/Rust 공개 API로 제공합니다. 완성 입력·폼·Dialog는 후속 단계이며 기존 예제의 내부 동작과 공개 기반 API를 구분합니다.
