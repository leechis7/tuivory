# 컴포넌트 배경색 전수 조사 — TVR-7

**한국어 (기본)** · [English](background-audit.en.md)

수정 후 현황: 사용자 후속 승인으로 [표면 디자인 규칙](../design/surfaces.md)과 [수정 검증](../evidence/background-fix.md)을 진행합니다. 아래는 수정 전 조사 기록이며 이전 해시·원시 관찰값을 보존합니다.

2026-10-29, 0.3.0 이후 메뉴·포커스 미커밋 소스를 포함해 조사했습니다. **글자 뒤 배경색이 컴포넌트 바탕과 다른 현상을 확인했습니다.** 이번 요청에서는 조사만 했으며 렌더러·토큰·예제 구현을 고치지 않았습니다. 기존 미커밋 작업은 보존했습니다. [정확한 결과·소스 해시](../evidence/background-audit-results.json).

## 범위와 판정 방법

- Go 47개 사례 × 12팔레트 = **564회**: 공통 모델/Rows 렌더러, Tree·탭·메뉴·경로·상태·패널·분할선, 기존 tview Styler의 직접 적용/Apply/Form 경로. Show 이후 실제 셀 Runes·Styles를 확인했습니다.
- Rust 32개 사례 × 12팔레트 = **384회**: 같은 공통 모델/Rows 경로와 독립 Tree·탭·메뉴/팝업·Line·패널/분할. Ratatui TestBackend 셀을 확인했습니다. 행 기반 위젯은 각 실제 모델의 layout 결과를 해당 공개 래퍼가 사용하는 같은 Rows 렌더러로 그렸습니다.
- 총 **948회**, 후보 팔레트 dark/light/blackwhite × 8/16/256/truecolor. 통제된 셀 비교는 48×12 ASCII 데이터로 문자 폭 영향을 분리했습니다.
- 현재 Rust 실행 예제 12개 장면의 한국어 144장(모든 프로필)과 dark-256 영어 대응 12장, 총 **156개** TestBackend 참조를 생성해 예제 조합도 확인했습니다. playground/일반 팝업·Tree·workspace·focus/팝업·menu·catalog 5모드입니다. Go 예제의 색상 연결은 소스와 기존 실제 Go 참조도 함께 대조했습니다.
- 바탕/글자/행 끝의 색상 차이는 관찰값이며 오류 개수가 아닙니다. 선택·입력·수정·줄무늬·테두리·앱 소유 자식 배경을 문맥별로 판정했습니다.

| 번호 | 확인 결과 | 영향/위치 |

## 모든 컴포넌트의 판정

| 컴포넌트 | 판정 |
| --- | --- |
| 폼·입력 | 라벨·일반 옵션·오류 문구의 문맥 누출 확인. 입력 영역(field)·버튼(button)의 별도 배경은 의도한 표현입니다. |
| Tree | 일반 노드·보조 설명은 surface에 맞춰져 정상. 선택 배경은 행 전체로 이어집니다. Go 자체 테두리와 선택 행의 차이는 정상입니다. |
| 목록 | 선택하지 않은 일반 항목에 누출 확인. 선택 배경이 글자 길이까지만 칠해지는 범위는 별도 디자인 검토 항목입니다. |
| 검색 선택기 | 검색 입력칸의 별도 배경은 정상. 결과의 일반 항목은 목록과 같은 누출입니다. |
| 메뉴·메뉴 바 | 일반 메뉴 본문은 surface를 사용해 정상. 선택은 전체 span을 채웁니다. 열린 메뉴의 바 항목 강조는 정상입니다. |
| 탭 | 비활성 body/활성 header의 색 차이는 상태 구분이며 탭 구간 전체에 칠합니다. 임의로 오류 처리하지 않습니다. |
| 패널 | 자체 바탕·테두리는 정상. Go 패널에 스타일을 지정하지 않은 외부 TextView를 넣었을 때 검정이 남는 것은 호스트 자식의 스타일 문맥 문제입니다. Rust 기본 Paragraph는 기존 바탕을 상속합니다. |
| 분할선 | surface와 divider/focus.border 연결은 정상입니다. |
| 경로 | 마지막 현재 경로 body 글자 뒤에 누출 확인. 앞 경로/hint는 정상입니다. |
| 상태 표시줄 | body 및 의미별 텍스트에서 누출 확인. 명시적 선택/수정 배경은 별도입니다. |
| 알림 | info/success/warning/error 문구의 배경 문맥 누출 확인. 아이콘·심각도 전경색을 유지하며 표면을 결정해야 합니다. |
| 진행 표시·스피너 | 기본 info 문구에서 누출 확인. 실제 진행 막대의 의미와 평문 배경을 구분해야 합니다. |
| 데이터 상태 | ready/loading/error 문구에서 확인. empty의 hint 배경은 기본 surface와 같습니다. |
| 배지 | 기본 body가 글자 길이의 다른 바탕을 만듭니다. 의도한 배지 바탕인지 정책이 명시돼 있지 않아 디자인 결정이 필요합니다. |
| 칩 | 배지와 같은 기본 body 경로입니다. 칩 전체 영역과 내부 글자의 바탕 규칙을 먼저 정해야 합니다. |
| 단축키 안내 | 일반 항목의 body 배경 누출 확인. disabled 항목은 surface와 같아 오히려 일반 항목만 띠처럼 보입니다. |
| 데이터 그리드 | simple의 UseSurface=false는 문서화된 canvas 배경 선택입니다. 셀 바탕과 빈 공간의 경계 일관성은 검토가 필요하지만 옵션 자체를 오류로 보지 않습니다. data의 UseSurface·현재 행·줄무늬·선택·수정 배경은 의도한 차이입니다. |
| 포커스·간격·밀도·Stack/Drawer 배치 | 상태/좌표 API 자체는 글자를 그리지 않습니다. 실제 내용의 배경은 결합한 렌더러/호스트가 결정합니다. |

## 재현되는 프로필

| 프로필 | body/canvas 배경 | surface/panel 배경 |
| --- | --- | --- |
| dark-256 | 236 (#303030) | 237 (#3a3a3a) |
| dark-truecolor | #2e3440 | #3b4252 |
| light-16 | 15 (참조 #ffffff) | 7 (참조 #c0c0c0) |
| light-256 | 255 (#eeeeee) | 254 (#e4e4e4) |
| light-truecolor | #f3f5f7 | #e4eaf0 |

위 5개에서 공통 평문 누출이 두 언어 모두 재현됩니다. 나머지 프로필에서는 두 배경이 같아 같은 경로의 문제가 겉으로 드러나지 않습니다. 입력/선택이나 Go 단독 스타일 helper의 기본 검정 문제까지 이 5개에 한정한다는 뜻은 아닙니다. ANSI 색상의 실제 RGB는 터미널 설정에 따라 달라집니다.

예: dark-256 Help의 `[Enter] Run`은 236, 뒤 빈 공간은 237입니다. 메뉴 일반 행은 처음부터 끝까지 237이고 선택 행은 처음부터 끝까지 24여서 문맥이 일관됩니다. 원시 셀의 예시는 결과 JSON의 illustrative_cells에 있습니다.

## 권장 수정 순서 (아직 수정하지 않음)

1. 공통 Rows와 Line 렌더러에 실제 그리는 표면 문맥을 연결합니다. 평문·보조 설명·단순 상태 글자는 바탕을 상속하고, field/button/selection/edited 같은 명시적 영역은 자신의 배경을 유지합니다. 사용자가 지정한 그리드/사용자 정의 역할의 배경을 일괄 덮지 않습니다.
2. 실제 바탕 위의 전경 대비를 재검증합니다. **light-16 success**의 참조 전경 #008000을 surface #c0c0c0에 그대로 옮기면 대비가 **약 2.82:1**로 낮아집니다. 이는 배경만 바꿨을 때의 계산이며 현재 렌더링의 새 대비 결함을 뜻하지 않습니다. Go 견본의 textOnSurface가 바탕 연결과 대비 보정을 함께 하는 기존 사례입니다.
3. Go/Rust 예제의 텍스트 영역과 기존 Go 직접 스타일 helper의 배경 연결 규칙을 맞춥니다.
4. 배지/칩·simple 그리드의 빈 공간·목록 선택 범위는 디자인 정책을 확정한 뒤 조정합니다. 전후 실제 출력과 테마/색상 변경 시 상태 보존을 검사합니다.

## 한계와 보존

실제 서버·SSH·폰트별 물리 터미널은 검사하지 않았습니다. 원격 CI·CentOS 검증·커밋·게시·릴리스도 수행하지 않았습니다. 렌더링 수와 텍스트 바탕 차이 수를 결함 개수로 해석하지 않습니다. Go 추출 Styler와 Go/Rust 후보 팔레트는 서로 다른 색상 체계로 나눠 조사했습니다. probe/원시 로그/156개 참조는 로컬 Git 제외 bin/validation/background-audit/에 있으며, 추적되는 결과 JSON에는 요약·대표 셀·소스/실행 근거 해시를 남겼습니다.
