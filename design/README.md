# Tuivory 공통 명세

**한국어 (기본)** · [English](README.en.md)

상태: 초안. Tuivory는 앱에서 재사용할 수 있는 TUI 컴포넌트와 스타일을 제공합니다. 이 명세는 패키지 간 일관된 테마·색상 프로필·컴포넌트 상태 구현을 위한 공통 기준입니다. 이 디렉터리의 명세와 [공통 토큰](tokens/README.md)은 언어와 독립적으로 관리합니다. 제품 정식 버전이나 외부 표준을 선언하지 않습니다.

## 명세의 범위

| 항목 | 공통 컴포넌트/명세 | 언어별 어댑터 | 앱 책임 |
| --- | --- | --- | --- |
| 색상·테마 | 의미 역할·전경/배경·프로필 | 프레임워크 색상 변환 | 테마·프로필 선택·단말 능력 감지·재적용 연결 |
| 상태 | 포커스·선택·수정·오류·비활성 합성 | 실제 위젯 표시와 상태 연결 | 원문·업무상 상태·실행 허용 판단 |
| 배치 | 셀 폭·최소 크기·영역 안의 분할/여백 계산 | 프레임워크 영역·스크롤·레이어 연결 | 화면 배치·순서·가시성·초기 크기 선택 |
| 입력 | 컴포넌트/정의된 스코프 내부 탐색·모달 차단/복귀 | 프레임워크 이벤트를 공통 동작에 변환 | 스코프 순서·영역 간 포커스·전역 키/명령 연결 |

세부 규칙은 [설계 원칙](../docs/principles.md), 컴포넌트별 명세는 [컴포넌트 패턴](../docs/patterns.md), 표현 능력은 [단말 프로필](../docs/terminal-profiles.md)에 둡니다. 중복된 별도 명세를 만들지 않고 이 문서들을 공통 기준으로 사용합니다.

## 토큰 해석 순서

1. 호스트가 테마와 표현 능력(8/16/256/truecolor)을 결정합니다. `auto`는 데이터 프로필이 아닙니다.
2. 토큰 로더가 해당 팔레트와 역할을 찾습니다. 없는 역할/프로필을 조용히 다른 값으로 대체하지 않습니다.
3. 어댑터는 ANSI 인덱스를 인덱스로, RGB를 RGB로 변환합니다. 참조 RGB는 검증용입니다.
4. 위젯이 실제 표면과 상태를 합성합니다. 색상 외에도 경계·밑줄·문구·표식으로 상태를 드러냅니다.
5. 스타일을 다시 적용해도 앱의 값·선택·포커스·스크롤은 보존합니다.

색상 토큰 JSON은 색상 역할과 굵기를 다룹니다. 배치 기본값은 별도 layout-tokens.json 초안으로 제공합니다. 간격·테두리·컴포넌트 상태 전체를 JSON으로 실행하는 엔진은 아직 없습니다. 간격·배치·동작 규칙은 위 문서에 있으며 후속 언어별 구현에서 검증합니다.

## 구현 간 검증

같은 입력 토큰은 모든 언어의 구현에서 동일한 값으로 읽혀야 합니다. `make check-consumers`는 Go/Python/Node.js가 12팔레트·192쌍을 그대로 읽는지 비교합니다. `make check-rust-consumers`는 Rust도 포함해 같은 데이터를 비교합니다. 이는 위젯 렌더링·키보드 동작의 동등성을 검증하지 않습니다.

위젯 어댑터를 추가할 때에는 테마 왕복 상태 보존, 선택/포커스 분리, 모달 입력 차단·복원, 작은 창과 한글 셀 처리를 해당 프레임워크에서 별도로 검사하고 [단말 증거](../evidence/README.md)를 남깁니다.

[공통 UI 점검](../docs/component-audit.md)과 [Tree 명세·구현](../docs/tree.md)은 이번 TVR-7 단계를 설명합니다. `tree-navigation.json`은 Go/Rust가 함께 검증하는 동작 시나리오이며 `tools/export_tree_cases.py`로 모듈 내부 테스트 사본을 생성합니다.

## 공통 상호작용 규칙

`interaction-cases.json`은 상태 역할·표식·실행/편집 허용, 포커스 이동·중첩 팝업·복귀·오류의 공통 시나리오입니다. `tools/export_tree_cases.py`로 Go/Rust 테스트 사본을 동기화합니다. 구체적 명세는 [상태·포커스·팝업](../docs/focus.md)에 두며 프레임워크 이벤트나 터미널 I/O를 공통 모델에 넣지 않습니다.

## 배치 기본값

`layout-tokens.json`은 compact/comfortable 간격과 셀 너비 경계 초안입니다. Go/Rust 코드는 같은 기본값을 내장하고 모듈별 테스트 사본으로 일치 여부를 검증합니다. 외부 런타임 파일이나 완성 JSON 배치 엔진을 추가한 것은 아닙니다. [배치 API](../docs/layout.md).

오버레이와 그림자의 양쪽 가로 경계에서 두 칸 문자가 잘리면 전체 grapheme을 공백 처리하고 바깥 스타일을 보존합니다. 호스트가 배경을 다시 그리며, 검사는 출력 반영 이후 버퍼를 확인합니다. [Go 구현과 검증 범위](../docs/overlay-drawing.md).

[TVR-17 그리드 옵션·우선순위·원문/호스트 경계](../docs/grid.md): 한 Go/Rust 코어의 simple/data 프리셋이며 미배포 소스입니다.

[컴포넌트와 앱의 책임](../docs/component-boundary.md)을 따릅니다. 예제 화면·키맵은 호스트가 선택한 조합이며 필수 앱 프레임워크가 아닙니다.

[공통 메뉴](../docs/menus.md): Go/Rust 계층·메뉴 바·뒤로가기·단축키/비활성·팝업·호출 문맥 요청과 DB 없는 한영 실행 예제. 기존 v0.2.0 태그에는 없는 미배포 소스입니다.

[표면·글자 배경 규칙](surfaces.md): 평문 바탕 상속, 명시적 상태 배경 보존, 대비 보정과 언어별 연결 API의 기준입니다.

[비활성 상태와 12팔레트 비교](../docs/disabled-states.md): 일반 비활성 접두사 제거, 회색/Dim 전경, 입력 차단과 한영 실행 예제.
