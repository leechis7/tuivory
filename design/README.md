# Tuivory 공통 명세

상태: 초안. Tuivory는 앱에서 재사용할 수 있는 터미널 UI 스타일 패키지를 제공합니다. 이 명세는 패키지 간 일관된 테마·색상 프로필·컴포넌트 상태 구현을 위한 내부 계약입니다. 이 디렉터리의 계약과 [공통 토큰](tokens/README.md)은 언어와 독립적으로 관리합니다. 제품 정식 버전이나 외부 표준을 선언하지 않습니다.

## 계약의 범위

| 항목 | 공통 계약 | 언어별 어댑터/앱 책임 |
| --- | --- | --- |
| 색상 | 의미 역할과 전경·배경 쌍, 명시적 단말 프로필 | 프레임워크 색상으로 변환, 단말 능력 감지 |
| 테마 | 같은 역할 이름, dark/light/blackwhite 참조 후보 | 사용자 테마 로딩, 화면 전체 재적용 |
| 상태 | 포커스·선택·변경됨·오류·비활성의 의미 | 위젯별 합성 순서, 실제 배경 대비 검증 |
| 배치 | 픽셀 대신 단말 셀, 한글 폭과 작은 창 대응 | 프레임워크별 측정·스크롤·레이어 구현 |
| 입력 | 영역 간 Tab 이동, 모달 포커스 가두기·복원 | 키 이벤트 변환, 앱별 키맵·작업 실행 |

세부 규칙은 [설계 원칙](../docs/principles.md), 컴포넌트별 계약은 [컴포넌트 패턴](../docs/patterns.md), 표현 능력은 [단말 프로필](../docs/terminal-profiles.md)에 둡니다. 중복된 별도 명세를 만들지 않고 이 문서들을 공통 기준으로 사용합니다.

## 토큰 해석 순서

1. 호스트가 테마와 표현 능력(8/16/256/truecolor)을 결정합니다. `auto`는 데이터 프로필이 아닙니다.
2. 토큰 로더가 해당 팔레트와 역할을 찾습니다. 없는 역할/프로필을 조용히 다른 값으로 대체하지 않습니다.
3. 어댑터는 ANSI 인덱스를 인덱스로, RGB를 RGB로 변환합니다. 참조 RGB는 검증용입니다.
4. 위젯이 실제 표면과 상태를 합성합니다. 색상 외에도 경계·밑줄·문구·표식으로 상태를 드러냅니다.
5. 스타일을 다시 적용해도 앱의 값·선택·포커스·스크롤은 보존합니다.

현재 JSON은 색상 역할과 굵기만 다룹니다. 간격·테두리·컴포넌트 상태 전체를 JSON으로 실행하는 엔진은 아직 없습니다. 간격·배치·동작의 계약은 위 문서에 있으며 후속 언어별 구현에서 검증합니다.

## 구현 간 검증

같은 입력 토큰은 모든 소비자에서 동일한 값으로 읽혀야 합니다. `make check-consumers`는 Go/Python/Node.js가 12팔레트·192쌍을 그대로 읽는지 비교합니다. 이는 위젯 렌더링·키보드 동작의 동등성을 검증하지 않습니다.

위젯 어댑터를 추가할 때에는 테마 왕복 상태 보존, 선택/포커스 분리, 모달 입력 차단·복원, 작은 창과 한글 셀 처리를 해당 프레임워크에서 별도로 검사하고 [단말 증거](../evidence/README.md)를 남깁니다.
